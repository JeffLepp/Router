====================================================================
2. CURRENT PIPELINE (branch testing)
====================================================================
main.py: read /input/tasks.json -> regex classify (agent/classify.py) ->
strict gate solves only explicit arithmetic locally (agent/gate.py) ->
everything else to Fireworks (agent/remote.py), one call per task, no
batching -> per-category contract builds prompt + assembles answer
(agent/contracts.py) -> atomic snapshots to /output/results.json.
Classifications with confidence < 0.8 use a "universal" contract: a format
menu listing all 8 categories' gold output schemas.
Gold output schemas (from dataset.json expected_answer):
  qa: bare string | math: bare number | sentiment: {"sentiment":...}
  ner: {"entities":[{"text","type"}]} | logic: {"answer":...,"valid":bool}
  summary: plain text (LLM-judged) | code: runnable fence-free code string.

4. RULED OUT (do not re-try without new evidence)
====================================================================
- Input truncation / "kernel" extraction: guaranteed zeros on long variants.
- Invented intermediate answer formats (NER text|TYPE lines etc.): only our
  own scorer ever parsed them.
- Lossy post-hoc rewriting (aspect alias maps, last-line extraction).
- Trusting practice-set (dataset.json) scores: 86-90% there coexists with
  42-58% hidden.
- Bigger token caps as an accuracy lever (Attempt 3).
- Dual-model agreement as implemented (Attempt 1 regressed).
- Local heuristic sentiment/NER/logic/code solvers as submission defaults:
  unproven OOD; gate stays strict-arithmetic-only until a variant-set
  precision suite passes 100%.

====================================================================
5. OPEN HYPOTHESES FOR THE 47.4% (ranked by evidence)
====================================================================
H1. [IMPLEMENTED 2026-07-11, next submission tests it] No cross-model
    failover on request ERRORS: agent/remote.py complete() used to switch
    models only on BLANK content; on repeated HTTP errors it retried the
    SAME model then gave up -> task scored zero. CATEGORY_MODEL_PATTERNS
    prefers gemma models for sentiment and NER. If the submission harness's
    ALLOWED_MODELS listed gemma IDs that were not actually callable
    (exactly the Attempt 5 failure signature), sentiment+NER (~25% of
    tasks) would blank out — a plausible cause of the 47.4%.
    Fix shipped: (a) hard failures (404/401/403, "model not found") are
    blacklisted per-run and every error rotates the call to the next-ranked
    different model; (b) a 1-token startup probe per allowed model
    (config: remote.probe_models) drops uncallable models before any task
    call. Transient errors rotate but never blacklist.
    Note: gemma names in CATEGORY_MODEL_PATTERNS are only preference
    regexes matched against the runtime ALLOWED_MODELS env; nothing
    hardcodes model IDs into the image. Merely "allowing" gemma cannot hurt
    — selecting a listed-but-broken model could, before this fix.
H2. Classifier/format coupling remains the ceiling: 34% classifier accuracy
    on paraphrased prompts; the universal fallback answers are measurably
    worse than correct per-category contracts (68.75% ceiling on variants2).
    Candidate fixes: (a) classify WITH the answer call — single contract for
    all tasks that both identifies type and answers (Kestrel-style); (b) a
    real local classifier (tiny ONNX/embedding, yassai-style); (c) spend one
    cheap remote call to classify batches of tasks (violates leader
    principle #1, but we are gate-failing, and it is ~200 tokens total).
H3. Reasoning was never the enemy: the best hidden score (57.9%) ran
    reasoning_effort=high with reasoning-model preference. Attempt 2 could
    not test this (dev pool had no reasoning models). If the submission
    pool has them, math/logic/code may want reasoning back ON with content
    (not reasoning_content) parsed as the answer and caps sized so the
    final answer survives.
H4. Hidden-set run-to-run variance: 42.1 / 57.9 / 47.4 came from three
    different builds, but prompts may also be resampled per submission.
    Do not over-fit to single-run deltas; submissions cost a 10/hr slot,
    consider A/B-ing one variable across two submissions.
H5. Summarization judging is opaque (semantic_similarity /
    contains_essential_points). We assume plain text is fine; nobody has
    validated what the hidden judge rewards (length? coverage? format?).
